# ショッピングエージェント {#shopping-agents}

ショッピングエージェントは、店舗側にSeamsやエージェントの導入を求めずに、EC店舗から購入します。
Seamsは、範囲を限定した委任条件と、ウォレットまたは決済用認証情報をエージェントに提供します。
その認証情報で購入できるのは、承認済みの制限内だけです。

## 委任条件の例 {#example-mandate}

指定した加盟店から承認済みの商品を購入する権限を、注文ごとの予算と有効期限を定めて、1つのエージェントに与えます。
最終的なカート、配送先、価格、配達日、加盟店が元の指示から外れる場合は、人による承認を求めます。

## 実行経路 {#execution-path}

```mermaid
flowchart LR
  Owner["ウォレット所有者"] --> Mandate["範囲を限定した委任条件"]
  Mandate --> Agent["権限を委任したエージェントのレーン"]
  Agent --> Intent["型付きの商取引の操作意図"]
  Intent --> Policy["加盟店、予算、リスク、有効期限"]
  Policy --> Approval["許可、拒否、追加確認"]
  Approval --> Rail["ウォレット決済またはバーチャルカード"]
  Rail --> Audit["領収書、返金、監査"]
```

カタログの閲覧には、ウォレットの権限を使わないでください。
価値の確保、資金の移動、注文の確定を伴う操作だけを、署名の経路へ進めます。
所有者の認証情報をローテーションせずに、エージェントのレーンを取り消せます。

加盟店が対応している場合は、ステーブルコインで直接支払います。
任意のバーチャルカードを使うと、カードのみに対応する外部店舗でも支払えます。
どちらの場合も、支払い実行前に、最終的な加盟店、商品、総額、有効期限、承認条件を委任条件へ紐づける必要があります。

[権限を委任したエージェント](/ja/guides/delegated-agents)と[ポリシーと委任条件](/ja/guides/policies-and-mandates)から始めてください。
