# デバイス連携・鍵のエクスポート・復元 {#add-devices-export-and-recover}

最初のウォレットで署名できるようになったら、これらの機能を追加します。
各操作は独自の承認と結果を持ちます。通常の署名とは別の処理として扱ってください。

## 別のデバイスをリンク {#link-another-device}

デバイス2がリンクセッションを開始し、QRコードを表示します。
デバイス1がコードを読み取り、新しいデバイスを承認します。

<<< ../../examples/device-linking.tsx

デバイス2では、`ShowQRCode`がリンクセッションを開始し、コードを表示します。
画面を閉じると、未完了のセッションをキャンセルします。
デバイス1では、`useDeviceLinking`が`onEvent`で進行状況、`onError`で失敗を通知します。
試行ごとに新しいコードを発行してください。

## 鍵をエクスポート {#export-a-key}

新たに承認した操作から`exportKey`を呼び出します。
エクスポート対象のレーンを選択し、ウォレットオリジンのエクスポートビューアーを開きます。

<<< ../../examples/export-wallet.ts

Ed25519のエクスポートは、ウォレットのNEARアカウントを使います。
ECDSAのエクスポートでは、設定済みチェーンを指定します。どちらも、既定ではログイン中のウォレットを対象とします。
ウォレット、アカウント、チェーンを明示する場合は、`walletSession`、`nearAccount`、`chainTarget`を渡してください。

レーンの選択はSDKが行い、選択したレーンをウォレットオリジンのビューアーへ直接渡します。
このデバイスに対象のエクスポートレーンや鍵素材がない場合、`exportKey`はレーンまたは鍵素材に関するエラーでrejectされます。

鍵素材はウォレットオリジンのビューアー内に表示されます。
アプリが受け取るのは`exported`などの結果であり、秘密鍵は含まれません。
エクスポートの内容を、ログ、URL、アクセス解析に含めないでください。

## ウォレットアカウントを復元 {#recover-a-wallet-account}

復元処理でウォレットに紐づくアカウント情報を復元する必要がある場合は、ウォレットレコードを同期します。

`syncAccount`は、既知のウォレットのアカウント状態を同期します。
復元コードの入力と新しい認証要素の検証は、ホスト型ウォレットメニューが担当します。
[ウォレットユーザーの復元](/concepts/custody/recovery-and-export#recovery)を参照してください。

<<< ../../examples/recovery.ts

`walletId`や`nearAccountId`を読む前に、`success`を確認してください。
同期が失敗するとヘルパーは例外を送出するため、呼び出し側で再試行の状態を表示できます。

## 権限の委任と鍵のローテーション {#delegation-and-rotation}

エージェントへの権限委任、レーンの更新、鍵のローテーションには、製品に応じたポリシーとデプロイの選択が必要です。
[権限を委任したエージェント](/ja/guides/delegated-agents)、[リンク済みデバイス](/ja/guides/linked-devices)、
[復元・エクスポート・鍵のローテーション](/ja/guides/recovery-export-and-rotation)から確認してください。

## 安全な再試行 {#safe-retries}

- キャンセルやセッションの期限切れの後は、新たな承認を求めてください。
- 古いセッションでエクスポートや鍵のローテーションを再試行しないでください。
- 署名を許可しなくなったデバイスや委任レーンは、権限を取り消してください。
