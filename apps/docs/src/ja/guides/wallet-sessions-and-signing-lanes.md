# ウォレットセッションと署名レーン {#wallet-sessions-and-signing-lanes}

再利用可能なウォレットセッションがなくても署名できます。
その場合、ユーザーは選択したレーンの認証方法で、対象の操作を個別に承認します。
`unlock`は、利用回数の上限と有効期限を持つ**ウォレットセッション**を作成します。
後続の要求は、その範囲内で承認を再利用できます。
各操作には引き続き、サーバー側の受け入れ判定と、検証済みの署名素材が必要です。

ロックすると、ウォレットの識別情報を維持したまま、再利用可能なセッションへのアクセスを解除します。

## アンロックで署名セッションを作成 {#unlock-provision-a-signing-session}

登録時に返された`walletId`を渡して、`unlock`を呼び出します。
成功結果には、NEARとEVM系の別々の分岐があります。`nearAccountId`は、NEARの分岐からだけ読み取ってください。

返されたウォレットセッションは、有効期限または利用回数の上限に達するまで、後続の署名呼び出しを支えます。
次の署名操作では、その操作だけを対象に、同じ方法で新たな認証を求めることができます。
再利用可能な許可を新たに作成する場合は、もう一度アンロックしてください。
セッションの期間と利用上限は、想定する一連の操作に合わせます。

## 署名メソッドを呼ぶ前に {#before-you-call-a-signing-method}

署名レーンは、ある種類の操作に使う鍵管理とポリシーの経路を識別します。
セッションの準備が完了したら、次を確認してください。

1. 準備完了の`WalletSession`を必要条件にします。
2. 検証済みのウォレット識別情報から、そのセッションの参照を作成します。
3. 検証済みの設定から、NEARアカウントまたはEVM系の対象チェーンを解決します。
4. 要求するレーンの準備が完了していることを確認します。
5. 操作の全体で、同じセッション参照を渡します。

処理全体の実装は、[署名](/examples/signing)を参照してください。

## 対処可能な状態を扱う {#handle-recoverable-states}

- 許可の期限切れや利用回数の上限に達した場合は、対象の署名操作に限って、同じ方法で追加認証できます。
  この追加認証で、別のレーンやエクスポートの権限は付与されません。
- 機能の準備が処理中の場合は、準備完了の状態になるまで待つ必要があります。
- ポリシーやノンスレーンが競合した場合は、再実行の前に状態を照合してください。
- ユーザーの操作確認をキャンセルすると、ウォレットの識別情報を変えずに、今回の操作を終了します。

進行状況イベントは、処理の状態を説明します。処理の分岐判断には、結果を表す判別可能なユニオン型を使ってください。
