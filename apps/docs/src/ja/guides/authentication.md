# 認証 {#authentication}

[ウォレットの設定と認証](/ja/examples/wallet-setup-and-authentication)で、プロバイダーの設定、ウォレットの登録、アンロックを確認してください。
このガイドでは、認証方法の選択と、各結果の状態の扱いを説明します。

## 認証の流れを選ぶ {#choose-a-flow}

- **アプリセッション**：信頼したバックエンドからの引き継ぎと、NEARの各操作に必要な新しい所有者承認は、
  [アプリのセッションと操作ごとの所有者承認](/ja/guides/application-auth)を参照してください。

- **Googleログインを設定の表示に再利用**：設定済みのGoogle IDと、所有者が承認したウォレットの関連付けを使います。
  アプリのログイン後に、`seams.auth.authenticate({ method: 'google', walletId, idToken })`を呼び出します。
  設定の読み取り権限を付与します。署名とセキュリティ設定の変更には、所有者の認証が必要です。
  トークンをバックエンドに保持するアプリは、`prepareExternalAuth`とブラウザーに結び付いた引き渡しを使います。
  設定、関連付け、ログアウト、失効の手順は[Google SSOガイド](/ja/guides/google-sso)を参照してください。

- **パスキー**：対応ブラウザーでの主な登録・アンロック方法です。
  ウォレットオリジンとRP IDが、認証情報を使用できる範囲を定めます。
- **GoogleとメールOTP**：アカウントの検出と、復元可能な第2の認証要素を組み合わせます。
  アプリはGoogleトークンを渡します。OTPと復元の状態は、ウォレットの処理が管理します。
- **VoiceID**：任意に追加できるブラウザーでの登録、アンロック、送金承認は、
  [VoiceIDの設定](/ja/concepts/auth-methods/voiceid)を参照してください。

## 認証状態を明示する {#keep-auth-state-explicit}

- 登録、アンロック、認証要素の追加を通じて、同じウォレットの識別情報を維持してください。
- 選択した署名APIの認可手順に従ってください。各操作には、その操作で必要な所有者証明と署名権限が必要です。
- キャンセル、期限切れ、再試行可能な配信失敗、ポリシーによる拒否を、それぞれ別の結果として表示してください。
- パスキー、セッショントークン、認証要素の秘密情報を、アプリやエージェントのストレージに保存しないでください。

各処理の境界は、[パスキー](/ja/concepts/auth-methods/passkeys)、[メールOTP](/ja/concepts/auth-methods/email-otp)、
[認証の境界](/ja/concepts/auth-planes)を参照してください。
