# ポリシーと委任条件 {#policies-and-mandates}

[署名](/ja/examples/signing)の実装から始め、型付きの要求にポリシーチェックを追加します。
ポリシーは、特定の主体が特定の操作を実行できるかを判断します。
委任条件（mandate）は、権限を委任した相手に許可する内容を記録します。

## 1つの操作を記述する {#describe-one-operation}

アクションの種類、主体、対象、チェーンまたはアカウント、有効期限、ノンスまたは要求の識別情報を含めます。
ポリシーが評価する金額や利用上限も含めてください。「何にでも署名できる」といった包括的な権限を付与しないでください。

## 署名前に評価する {#evaluate-before-signing}

1. アプリまたはサービスの境界で要求を検証します。
2. 対象のウォレットセッションと署名主体を解決します。
3. 許可範囲、要求の鮮度、利用上限、権限の取り消し、追加認証の条件を評価します。
4. 操作の内容を、人が理解できる形式で表示します。
5. 操作に署名します。
6. 判断の結果と証跡を記録します。

ポリシーによる拒否は、想定される結果の1つです。
非公開のポリシー入力を明かさずに、満たさなかった条件と、次に実行できる対処を説明してください。

用語の詳しい説明は、[ポリシーモデル](/ja/concepts/policy/)と[委任条件](/ja/concepts/policy/mandates)を参照してください。
