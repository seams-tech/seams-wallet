# 結果と対処可能なエラー {#results-and-recoverable-errors}

公開操作は、複数の型の結果を返します。`success`や`ok`がある場合は、最初に確認してください。
次に、分岐固有の`kind`、`status`、エラーコードを確認します。
一部の署名メソッドは、キャンセルや失敗時にPromiseを拒否します。戻り値の確認に加え、例外も処理してください。

## 登録 {#registration}

`RegistrationResult`は、失敗とウォレット作成の成功を分けます。
成功結果は、利用可能な機能の分岐か、プロビジョニング待ちの状態を示します。
`walletId`は、ウォレットの安定した識別子です。
チェーン固有のアカウントデータは、該当する機能やプロビジョニングの分岐に含まれます。

一致する結果分岐からフィールドを読み取ってください。
登録の成功は、要求したすべての署名機能の準備完了を保証しません。
NEARの準備待ちの場合は状態を監視し、準備完了の分岐からのみ続行してください。

## ログインとセッション {#login-and-sessions}

`LoginResult`は、エラー文字列を含む`success: false`か、`near_wallet_unlocked`または`ecdsa_wallet_unlocked`を含む`success: true`を使います。
`nearAccountId`を持つのは、NEARの分岐だけです。
`LoginAndCreateSessionResult`は、`signingSession`を含む場合もあります。
再利用可能な利用枠を有効と扱う前に、`status`を確認してください。署名時は、正確なウォレット識別情報を保持してください。

## 署名とアクション {#signing-and-actions}

`ActionResult`、`SignNEP413MessageResult`、EVM系の結果は、各操作が公開する範囲で、キャンセル、ポリシーによる拒否、通信失敗、送信受理、確定を別の結果として保持します。
現在の分岐に対応する対処方法を、ユーザーに表示してください。

## 鍵のエクスポート {#key-export}

`seams.keys.exportKey()`は、ウォレットオリジンのビューアーが開くと、`{ kind: 'exported' }`を返します。
秘密鍵をアプリへ返すことはありません。
対象レーンの欠落、素材の欠落、完全なログインの要求は、Promiseの拒否になります。独自UIで処理してください。

デバイス連携の有効化は、型付きの拒否と整合性エラーの分岐を公開します。
結果の型の各分岐を処理してください。

## エラー処理の規則 {#error-handling-rule}

1. 結果ユニオンの全分岐を処理してください。
2. 秘密情報を除き、安定したコードと操作の識別情報を記録してください。
3. 再試行可能と記載された分岐だけを再試行してください。
4. セッションやポリシーの分岐が要求する場合は、新たなユーザーの存在確認を求めてください。
5. 送信状態が不明な操作を再実行する前に、チェーンの状態を照合してください。

進行状況の表示には[イベントと進行状況](/ja/reference/events-and-progress)を、一般的な対処には[トラブルシューティング](/ja/deploy-and-operate/troubleshooting)を参照してください。
