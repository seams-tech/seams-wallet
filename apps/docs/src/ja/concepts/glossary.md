# 用語集 {#glossary}

パスキーとメールOTPは、リリース済みの所有者認証方法です。
SDK 0.25.0では、任意の[VoiceID](/ja/concepts/auth-methods/voiceid)を追加します。
委任エージェントの発行と、より広い決済アダプターは計画中の機能です。
利用可能なAPIとして扱う前に、[リリース状況](/ja/releases)を確認してください。

| 用語                                   | 意味                                                                                                                                       |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 認証の境界（Auth plane）               | アプリログイン、ウォレットセッション、機能の許可、委任の許可、API認証情報など、1種類の権限の境界。                                         |
| 認証情報（Credential）                 | ポリシーが使う証明入力。パスキー、メールOTP、VoiceID、デバイス・組織ロール・ウォレットの証明、設定済み外部認証情報など。                   |
| Deriver A / Deriver B                  | 登録、エクスポート、更新、復元、有効化など、導出時の操作で使う分離したサーバーロール。                                                     |
| 委任エージェントのレーン               | ポリシーの下で、エージェントやサービスへ発行する独立した署名レーン。                                                                       |
| 保持者のシェア（Holder share）         | しきい値鍵のうち、ユーザー、デバイス、エージェント、認証方法側が持つ部分。                                                                 |
| リンク済みデバイスのレーン             | ユーザーが管理する別のデバイスへ発行する独立した署名レーン。                                                                               |
| 委任条件（Mandate）                    | ポリシーの下で対象が実行できる内容を定める、署名済みで範囲を限定した権限オブジェクト。                                                     |
| ポリシーのエポック                     | 取り消しを考慮する判断に使う、バージョン付きのポリシー状態。                                                                               |
| Router                                 | 認証、ポリシー、リプレイ、利用枠、予算、リクエストのルーティングを扱う公開サービス境界。                                                   |
| サーバーのシェア（Server share）       | しきい値鍵のうち、ホスト型またはセルフホストのサーバーが持つ部分。                                                                         |
| テナント導出ルート                     | テナントごとに独立した乱数で作るサーバー側の導出元。A/B別々の運用シェアとして保持する。                                                    |
| ウォレットのカストディシード           | 1つのウォレットのランダムな秘密。所有者署名ルートは、それぞれ独立してここから導出する。                                                    |
| 所有者署名ルート                       | シードから導出するEd25519 Yao ClientルートまたはECDSAクライアントルートシェア。一方から他方を導出しない。                                  |
| レーン保持者のシェア                   | 署名プロトコルが用意するレーン単位の素材。シード導出から独立し、復元セットには含まれない。                                                 |
| `signingRootId` / `signingRootVersion` | 署名ルートについての永続的な識別子。鍵素材を含まない。                                                                                     |
| 鍵管理のセレモニー（Custody ceremony） | 所有者ルートを導出し、ウォレット鍵マニフェストを検証する登録または復元の手順。認証要素の追加とアンロックは、エンベロープの認証を維持する。 |
| テナントルートの運用シェア             | 1つのDeriverが持つテナントルートの秘密シェア。更新は、有効なルートを維持してペアを変更する。                                               |
| シェアのエポック                       | 運用シェアの世代を示すメタデータ。鍵素材を含まない。                                                                                       |
| 鍵管理の系統（Custody lineage）        | 1つのテナントルートの鍵管理ライフサイクルの識別情報。復元先ごとにコマンドとリプレイ状態を分離する。                                        |
| 管理型テナントルートのバックアップ     | 承認済みの管理型復元経路が使う、サービス保有の暗号化ロールシェアのバックアップ。                                                           |
| テナント復元セット                     | 正確なルートの復元用にテナントが保持するA/B復元パッケージと公開マニフェスト。ウォレットの移行とは別。                                      |
| SigningWorker                          | 有効化済みのサーバー署名素材を使う、通常署名用のサーバーロール。                                                                           |
| ウォレットセッションの利用枠           | 有効期限と残り回数の上限を持つ、再利用可能な署名の許可枠。                                                                                 |
| 機能の許可（Capability grant）         | 正確な機能と操作意図に紐づく、1回の操作権限。                                                                                              |
| 署名レーン                             | 1回の操作で選択する、正確な署名機能。                                                                                                      |
| 署名済み委任条件                       | ポリシーに紐づく、ユーザー、組織、ウォレット、デバイス、エージェントの権限オブジェクト。                                                   |
| Streaming Yao                          | Ed25519のライフサイクル手順でDeriver AとBが使う、固定回路の二者計算。ガーブルドテーブルをAからBへ直接ストリーミングする。                  |
| しきい値セッション                     | 特定の曲線とセッションのプロトコル識別情報と署名素材。署名には操作の承認も必要。                                                           |
| ウォレットのホーム                     | 1つのウォレットに割り当てる固定リージョン。すべてのデバイスと後続操作が使う。                                                              |
| 型付き操作意図のダイジェスト           | 承認・実行対象となる正確なアクションの正規化ダイジェスト。                                                                                 |
| ウォレットセッション                   | 署名と利用枠のルートが使う、ウォレット利用者の操作権限。                                                                                   |
