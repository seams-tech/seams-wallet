# 認証の境界 {#auth-planes}

Seamsは、ログイン、ウォレット権限、署名の利用枠、委任実行を分離します。
各ルートや操作は、1種類の権限を扱う、主となる認証の境界に属する必要があります。

| 境界                         | 目的                                                         |
| ---------------------------- | ------------------------------------------------------------ |
| アプリセッション             | アプリやIDプロバイダーへのログインを証明する。               |
| ウォレットセッション         | 再利用可能なウォレット利用者の操作を許可する。               |
| しきい値セッション           | 曲線固有のプロトコル状態と署名素材を識別する。               |
| ウォレットセッションの利用枠 | 再利用可能な署名の有効期限と残り回数を定義する。             |
| 機能の許可                   | 1つの正確な操作と機能の利用を承認する。                      |
| 委任の許可                   | 委任実行のポリシーと監査のオブジェクト。                     |
| API認証情報                  | 範囲を限定したプロジェクト・サーバールート用の機械認証情報。 |

ホストアプリへのログインとConsole管理者のログインは、範囲が異なります。
どちらも、ウォレットへの署名権限を与えません。
しきい値セッションの識別子にも、署名前に正確な操作の承認と検証済み素材が必要です。

アプリセッションだけでは、取引署名、鍵のエクスポート、デバイス連携、エージェントレーンの発行、委任実行を承認できません。

## 分離する理由 {#why-it-matters}

各境界は、異なる問いに答えます。

1. 誰がログインしているか。
2. どのウォレット操作を許可するか。
3. どの正確な署名レーンが参加できるか。
4. どの利用枠や委任条件を消費するか。
5. 取り消しとリプレイを確認した後も、その要求を実行できるか。

これらを分離すると、広い用途のログイントークンがウォレット署名権限になることを防げます。
