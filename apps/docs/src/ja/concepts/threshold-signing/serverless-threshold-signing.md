# サーバーレスのしきい値署名 {#serverless-threshold-signing}

Seamsは、Cloudflareにデプロイできる、セルフホスト可能なしきい値方式の組み込みウォレットを提供します。
しきい値署名と秘匿シェアの導出を使います。
通常署名は署名シェアを生成し、単一ランタイムが本来の秘密鍵を組み立てる必要はありません。

## 署名の境界 {#signing-boundary}

通常署名の経路は、シェアに基づきます。

```text
保持者側の署名シェア + 受付済みのサーバー側署名シェア -> 署名
```

保持者側の素材は、ウォレットオリジンのランタイム境界内にあります。
サーバー側の素材は、Router受付、Worker認証、ポリシー、リプレイ、利用回数、署名利用枠、レーンへの紐づけの背後にあります。

通常署名中に、ウォレットiframe、Router、SigningWorkerで本来の秘密鍵を再構成しません。
エクスポートは、新たな承認、監査記録、公開鍵の一致確認を伴う、別の操作です。

## ロールを分けた導出 {#split-role-derivation}

Ed25519素材は、Deriver AとB間のStreaming Yaoで生成します。
ECDSA素材は、厳密なしきい値PRF導出と加算スカラーシェアを使います。
各ロールは、利用を許可された出力だけを受け取ります。

- クライアントとブラウザーWorkerは、保持者側署名素材またはハンドルを受け取る。
- Routerは、公開のルーティングとポリシーの状態を受け取る。
- Deriverは、ロール内のプロトコル状態を受け取る。
- SigningWorkerは、有効化済みサーバー署名素材と1回限りの事前署名状態を受け取る。

曲線固有のフローは、元のルート素材を1つのプロセス内で結合せず、互換性のある署名シェアを導出します。
より強いサーバー実行時の境界が必要な場合、同じしきい値署名モデルを保ち、機密性の高いロールをTEE内へ配置できます。

## Cloudflareでのセルフホスト {#cloudflare-native-self-hosting}

Seamsは、セルフホスト可能で、サーバーレス構成に対応しやすい設計です。
Cloudflare Workers、Durable Objects、リージョンD1、WASMにコンパイルしたRust計算で、分割ロールを実行できます。
各サービスには、個別のリクエスト、保存、計算の料金があります。リージョンの配置で使用料が無料になるわけではありません。

試作から本番への、実用的な経路を提供します。

- 採用した同一アカウントP0構成を、本番、ステージング、ローカルの同等構成、ベンチマークに使う。
- Router、Deriver、SigningWorkerのロールを分離する。
- Workerのルーティングと、ウォレットが管理するDurable Object計算を、需要に応じて拡大する。
- 運用上の分離を強めても、同じウォレット構成を維持する。

小規模チームは、これらの管理型サービスでモデルを試せます。
大規模環境は、同じプロトコル構成に、非公開バインディング、分離Worker、専用ストレージ、TEE、厳密なリリース制御を追加できます。
強いランタイム構成には、別の適格性確認が必要です。
独立管理のDeriverアカウントは、再接続の信頼性と遅い側の遅延条件を満たすまで、延期中の強化構成です。

デプロイ可能なランタイムアセットと開発例は、計画中の本番移行製品とは別に利用できます。
R122は、顧客向けデプロイコンパイラー、ウォレットのインポート、継続性検証、明示的な切り替えを追加する計画です。
開発用デプロイは、移行の保証やA/B管理の独立した分離を証明しません。

R120の管理型テナントルートバックアップも、移行可能なウォレット一覧を構成しません。
R121は正確なルートのテナント管理復元を、R122はウォレットとデプロイ環境の移行を扱います。
現在の提供状況は、[復元と移行](/ja/deploy-and-operate/recovery-and-portability)を参照してください。
