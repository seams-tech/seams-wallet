# 認証情報と証明 {#credentials-and-proofs}

証明入力は、正確な承認を支えます。
誰が操作し、どの権限を持ち、どの操作意図を承認し、その権限がまだ使えるかを示します。

## 証明入力 {#proof-inputs}

リリース済みウォレットは、パスキー、メールOTP、ウォレットセッション、リンク済みデバイスの証明を使います。
組織のロールは、Consoleの承認に属します。
SDK 0.25.0では、任意の[VoiceID](/ja/concepts/auth-methods/voiceid)認証を追加します。
外部の生体認証証明は、引き続き提案段階の入力です。
次の一覧は、ポリシー上の意図する役割を示します。公開登録APIの一覧ではありません。

1. パスキー・WebAuthnによる存在確認。
2. メールOTPの検証。
3. VoiceIDによる所有者の存在確認。
4. ウォレットセッション、利用枠、操作の機能許可の状態。
5. デバイスまたはリンク済みデバイスの証明。
6. 組織のロールの証明。
7. 設定した外部ID、生体認証、認証情報の証明。

## 承認時の問い {#authorization-questions}

```text
誰が操作しているか。
どの権限を持つか。
どの操作意図を承認したか。
その権限を今も使えるか。
```

ポリシーは、実行を許可する前に証明を評価します。
ウォレット署名、支払い、エージェントのツール呼び出し、加盟店APIの呼び出しは、必要な証明とポリシーの確認に成功した後だけ実行します。
