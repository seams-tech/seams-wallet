# VoiceID {#voiceid}

VoiceIDは、任意のブラウザー認証方法です。
アプリが対応を有効にした後、各ウォレットの所有者が登録するかどうかを選びます。
話者照合と発話認識は、信頼するWallet iframe内でローカル実行します。
鍵管理、セッション、ポリシー、しきい値署名の既存の確認は維持されます。

## インストールと設定 {#install-and-configure}

アプリには同じバージョンのパッケージをインストールしてください。
`VERSION`を[リリースノート](/ja/releases)に記載された対応するバージョンに置き換えます。

```sh
pnpm add @seams/wallet@VERSION @seams/voiceid@VERSION
```

任意のパッケージから記述子をインポートし、既存の設定に`authMethods`を追加します。
次の例はNEARとArcのテストネットを有効にします。

<<< ../../../examples/voiceid.ts#configuration

[ウォレットの設定と認証](/ja/examples/wallet-setup-and-authentication#configure-the-provider)に従い、設定を`SeamsWebProvider`へ渡してください。
記述子のインポートと対応の有効化では、エンジンやモデルをダウンロードしません。
パスキーとメールOTPの処理でもVoiceIDアセットを読み込みません。
発話認識モデルの初期設定はCitrinet-256 LSです。容量の小さいAuroraASR-1Mを使う場合は、
`voiceIdAuthMethod({ transcriptionModel: 'aurora' })`を設定します。
ダウンロードする発話認識モデルは選択したものだけです。モデルを変更しても、保存済みの話者登録は維持されます。

## Walletホストの準備 {#prepare-the-wallet-host}

`walletOrigin`の運用者も、両方のパッケージを同じバージョンでインストールする必要があります。
別の運用者がWalletをホストする場合は、そのオリジンでのVoiceID対応を依頼してください。

インストール後、ホスト側のプロジェクトで次のコマンドを実行します。

```sh
npx --no-install seams-voiceid-host ./wallet-with-voiceid
```

コマンドは、インストール済みのWalletパッケージを自動検出します。pnpmの配置にも対応します。
Walletと任意のVoiceIDのアセットを、指定した出力ディレクトリーへまとめます。
ビルドごとに新しい出力ディレクトリーを使ってください。既存ディレクトリーやインストール済みパッケージは上書きしません。

出力ディレクトリーを、`walletOrigin`の静的ルートとしてデプロイしてください。
`/wallet-service`、`/sdk/*`、アセットマニフェストを含みます。
マニフェストに記載されたContent-Typeとキャッシュヘッダーを維持してください。
ホストの要件は[ホスト型統合](/ja/deploy-and-operate/hosted-integration)を参照してください。

ホストは、有効なVoiceID操作で必要になったときだけ`/sdk/voiceid/host.js`を読み込みます。
ホストへの配置が欠けている場合や互換性がない場合は、設定エラーを返します。

## ウォレットへの登録 {#enroll-a-wallet}

所有者は、まずパスキーまたはメールOTPでウォレットをアンロックします。
次にWalletメニューの**認証方法 → VoiceID**を開きます。
アプリ独自の**VoiceIDを有効にする**操作も用意できます。

<<< ../../../examples/voiceid.ts#activation

プロバイダー内で`useSeams()`から`seams`を取得します。
ユーザーのクリック後、現在のウォレットIDとともに`enableVoiceId`へ渡してください。
Walletは、マイクの許可と、受け入れた3つのサンプルを管理します。
拒否されたサンプルは再試行できます。画面を閉じると`kind: 'cancelled'`を返します。
登録に成功すると`walletAuthMethodId`を返します。現在の認証方法は変わりません。
登録済みの方法で再度有効化を呼ぶと、**音声の管理**を開きます。

## アンロックと送金承認 {#unlock-and-approve-transfers}

所有者はWalletのサインインメニューでVoiceIDを選べます。
独自のアンロック操作には、ウォレットIDと登録済みの`walletAuthMethodId`を渡します。

<<< ../../../examples/voiceid.ts#unlock

VoiceIDでアンロックした後も、既存の[トランザクションAPI](/ja/examples/signing)を使います。
NEARとArcのテストネット送金の確認画面に、**VoiceIDで確認**を表示します。
所有者は、表示された短い英語の発話を普段の速さで読みます。
各確認で新しい音声照合が必要です。実験用の話者の類似度しきい値は**0.45**です。
発話認識では、自然な発話に対応するため、一定範囲の違いを許容します。
表示された発話で鮮度を確認します。承認する操作はトランザクションの確認画面で定まります。

VoiceIDの有効化や登録だけでは、パスキーやメールOTPでの署名方法は変わりません。
署名者や認証方法の追加、登録音声の変更では、引き続き操作単位の承認を求めます。

## 読み込みと保存 {#loading-and-storage}

初回のVoiceID操作では、転送時の圧縮前でCitrinetなら約**36 MB**、Auroraなら約**27 MB**をダウンロードします。
1つの進捗表示で、エンジン、話者モデル、音声検出モデル、選択した発話認識モデルの読み込み状況を示します。その後、推論の準備が終わるまで**VoiceIDを準備中…**を表示します。
ブラウザーの保存領域が利用可能な場合、検証済みのアセットをキャッシュします。
サイトデータの削除やブラウザーによるキャッシュ削除で、再ダウンロードが必要になる場合があります。

音声はローカルに留まり、処理後に破棄します。Walletオリジンは、登録テンプレートとデバイス認証情報を保存します。
登録と追加サンプルには、時間や利用回数の制限がありません。
登録を削除した場合やWalletオリジンの保存領域を消去した場合は、再登録が必要です。
**音声の管理**では、所有者の新たな確認後に認識の改善、リセット、再録音を行えます。

VoiceIDは、そのブラウザーのデバイス認証情報とローカルの話者照合に依存します。
録音音声や合成音声への耐性について、本番環境での精度を保証しません。
登録音声の管理に備え、パスキーまたはメールOTPを利用可能にしてください。

## 現在の対象範囲と今後の改善 {#current-scope-and-future-improvements}

VoiceIDはWallet iframe内で話者と読み上げたフレーズを照合します。
サーバーは、登録済みのブラウザーのデバイス鍵による署名を検証します。
Walletのコードは、その鍵を使う前に音声を照合します。
署名だけでは、録音や話者照合の結果を独立して証明できません。
現在のVoiceID承認は、確認画面を伴うNEARとArcのテストネットのネイティブ送金に対応します。

話者照合のしきい値**0.45**とフレーズ照合の範囲は実験段階です。
これまでの少数の実音声記録では、本人の承認率や、録音の再生・合成音声への耐性を確認できていません。

今後の改善候補は次のとおりです。

- 同意を得た録音で、短いフレーズの承認率を改善します。
  照合条件を変える前に、別のフレーズや否定語を変えた発話が拒否されるか確認します。
- 複数の話者、別の日の録音、再生音声、合成音声を使い、本人の拒否率と別人の承認率を測ります。
- モバイルブラウザーで初回ダウンロード、メモリー使用量、判定時間を測ります。
  AuroraのFP16を追加する前に、同じ録音でINT8と比較します。
- より強いデバイスの証明や承認できる操作の拡大は、別の変更として検討します。
  Walletの確認画面、セッション制限、署名時の確認を維持します。
