# VoiceID {#voiceid}

このページは、提案段階の承認方法を説明します。
公開済みWallet SDKは、VoiceIDの登録・認証APIを提供しません。

VoiceIDは、所有者の存在確認のシグナルです。署名を制御するのは、しきい値署名とポリシーです。

VoiceIDは、登録済みの話者、音声コマンド、デバイスの状況、鮮度、ポリシー制約を検証します。
特定の署名フローを続行できる、短時間の承認結果を発行できます。

VoiceIDは、特定フローの承認シグナルです。
ウォレット秘密鍵、署名の秘密、復元の秘密、アカウント認証情報、単独の署名権限ではありません。

## フロー {#flow}

```text
SDKのトランザクション要求
  -> 正規化した操作意図のダイジェスト
  -> 登録済みデバイスでVoiceIDコマンドを収録
  -> 話者、発話、鮮度、デバイスを確認
  -> ウォレットポリシーの判定
  -> 1回限りの所有者存在確認の機能許可
  -> 通常のRouter A/B署名を続行
```

## ポリシーのモード {#policy-modes}

直接の機能許可は、低リスクで、1回限りの、操作意図に紐づくアクションだけに適しています。

リスクの高い処理では、VoiceIDを最初の確認に使います。
その後、パスキー、メールOTP、スマートフォン、腕時計などで新たな認証を求めてください。
対象は、エクスポート、復元、新規デバイス登録、高額署名、新しい宛先への署名、通常と異なるセッションです。

## 要件 {#requirements}

1. 声の照合と、発話・操作意図の文字起こしを分離する。
2. 音声コマンドを、取引と同じ`intentDigest`へ紐づける。
3. セキュリティモデルで、証明とデバイスの紐づけを必須とする。
4. 音声テンプレートと生音声に、明示的な保持規則を設ける。
5. 高リスクのフローには、追加認証を要求する。
