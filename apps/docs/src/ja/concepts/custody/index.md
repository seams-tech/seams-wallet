# 資産管理モデル {#custody-model}

Seamsは、ホスト基盤だけではウォレット署名や鍵のエクスポートができない、非カストディ型の仕組みです。
署名には、保持者側の参加と、選択したレーンに対応するサーバー側素材が必要です。
リクエストは、ウォレットセッションの受付、ポリシー、リプレイ、利用回数、予算の確認に成功する必要があります。

エクスポートは、新たな承認を伴う独立したフローです。
通常署名はシェアと事前署名状態を使い、完全な秘密鍵を再構成しません。

## 各場所が保持するもの {#who-holds-what}

| 場所                   | 保持できるもの                                                         | 保持してはいけないもの                                                                      |
| ---------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| アプリオリジン         | 公開ウォレットID、要求する操作意図、秘密を含まないSDK状態。            | 保持者・サーバーのシェア、PRF出力、メールOTP秘密素材、VoiceIDテンプレート、ルートシェア。   |
| ウォレットiframe       | ウォレットUI状態、暗号化IndexedDBレコード、セッションマーカー。        | サーバールートシェア、Deriver A/Bの平文、無関係なウォレットオリジンのレコード。             |
| ブラウザーの署名Worker | 使用中の保持者素材、コンパクトなライフサイクル入力、操作内の秘密情報。 | Deriver A/Bのルートシェア、結合したサーバー寄与。                                           |
| メールOTP Worker       | メールOTP要素から導出した秘密素材、使用中の署名ハンドル。              | 承認済みエクスポートフロー外の平文エクスポート出力。                                        |
| Router                 | 公開ルーティング情報、ポリシーの判断、セッション受付、リプレイ状態。   | 平文の保持者シェア、ルートシェア、結合したウォレット秘密鍵。                                |
| Deriver A              | A側の封印したルートシェアとプロトコル状態。                            | B側ルートシェア、結合したルート、結合したウォレット鍵。                                     |
| Deriver B              | B側の封印したルートシェアとプロトコル状態。                            | A側ルートシェア、結合したルート、結合したウォレット鍵。                                     |
| SigningWorker          | 有効化したサーバー署名素材、1回限りの事前署名状態。                    | クライアント保持者シェア、エクスポートしたウォレット鍵、Deriver A/Bの管理するルートシェア。 |

## 鍵管理の不変条件 {#custody-invariants}

### テナント導出ルート {#tenant-derivation-roots}

R120は、テナントごとに独立した乱数のサーバー側導出ルートを提供します。
Deriver AとBは、自身の暗号化運用シェアだけをロール専用D1に保持します。
各ロールは、自身のR2バケットに別々に暗号化した管理型バックアップを保持します。
Routerは、公開ライフサイクル状態と記録を調整します。

テナントルートシェアは、導出の手順を支えます。
ウォレットのカストディシード、クライアント署名ルート、準備済み保持者・SigningWorkerの署名シェアは、それぞれ別の鍵管理経路を持ちます。
テナントルートシェアの更新は、ルートとウォレット識別情報を維持します。
ウォレットのシードを置き換えたり、ウォレットの鍵を交換したりしません。
[テナントルートのバックアップ](/ja/deploy-and-operate/tenant-root-backups)を参照してください。

### 署名と承認 {#signing-and-authorization}

1. Routerは単独で署名できない。
2. 片方のDeriverは単独でサーバーの寄与全体を導出できない。
3. SigningWorkerはウォレット鍵をエクスポートできない。
4. アプリオリジンのコードは公開結果を受け取る。エクスポートした鍵は、ウォレットオリジンのビューアー内に留まる。
5. エージェントとリンク済みデバイスは、レーンに限定した権限を受け取る。
6. 署名処理の前に、取り消し、有効期限、利用枠の消費を確認する。

## 復元と移行 {#recovery-and-portability}

ユーザーは、ウォレットに設定済みの認証方法と復元素材で、アクセスを復元できます。
エクスポートは、新たな承認、ルートのポリシー、正確なレーンへの紐づけが必要な機密操作です。

R121のテナント管理の復元は、正確な論理テナントルートを、新しい鍵管理系統を持つ空の移行先へ復元します。
R122で計画する移行は、明示的な識別対応と切り替えで、ウォレット一覧と署名参加者を移します。
テナントルートの復元だけでは、ウォレットレコード、署名レーン、ドメイン、権限は移りません。
提供状況とアセットの境界は、[復元と移行](/ja/deploy-and-operate/recovery-and-portability)を参照してください。
