# リリース 0.62.0

ブラウザーSDK、サーバーSDK、VoiceIDプラグイン、Speak-to-Signプラグインは **0.62.0** を使います。

- SigningWorkerの古い状態エポックのNEARカストディのキャッシュを、Routerとの通信なしにこのデバイスで再バインドするようになりました。
  - Walletのフレームのストレージはサイトごとに分かれています。そのため、別のサイトや別のデバイスでのウォレットの最初のパスキーのログインはキャッシュを見つけられず、Routerの復旧を行います。復旧は状態エポックを進めます。
  - 復旧はクライアントとSigningWorkerのシェアを変えません。そのため、このサイトの古いキャッシュは現在のシェアを持っています。Walletは、サーバーの現在のSigningWorkerの検証シェアと登録済みの鍵でそれを確かめ、現在のエポックで封印し直します。
  - パスキーのログイン、アカウントの同期、VoiceIDのアンロック、Email OTPのアンロック、Email OTPのエクスポートがこれを行います。以前は、VoiceIDのアンロックが「Something went wrong.」で失敗し、パスキーのログインがRouterの復旧をもう1回行っていました。
  - キャッシュのないサイトでは、VoiceIDやEmail OTPの前に、引き続きパスキーのアンロックが1回必要です。この手順は今後のリリースでなくします。
- 有効なEd25519のケイパビリティは`signingWorkerVerifyingShare`を持ちます。パスキー、Email OTP、VoiceIDのアンロックの応答がこれを返します。
- 鍵セットに再参加したパスキーのログインは、復旧を報告するようになりました。そのため、ローカルの権限とWallet Sessionの記録は新しいマテリアルのアクティベーションに従います。0.61.0では、古いキャッシュのための再参加の後、これらが古いアクティベーションのままでした。
- `@seams/speak-to-sign` 0.62.0は、空の`./react`エントリーを削除します。
- Speak-to-SignのホストAPIはバージョン **8**、VoiceIDのホストAPIはバージョン **10** のままです。
- サーバーとWalletホストを一緒にデプロイし、アプリを0.62.0に更新してください。0.61.0のWalletのEmail OTPのアンロックは新しいケイパビリティのフィールドを拒否し、0.62.0のWalletはそれを必要とします。0.61.0のWalletのパスキーとVoiceIDのアンロックは、0.62.0のサーバーでも動き続けます。
- 4つのパッケージをすべて0.62.0でインストールしてください。Speak-to-Signは引き続き実験的機能で、NEARテストネット専用です。実際の資金では使わないでください。

ウォレットのiframeプロトコルは **23.0.0**、ウォレット管理プロトコルは **5** のままです。
署名付きの復旧CLIは **0.29.0** のままです。このリリースはデータベースのマイグレーションを追加しません。
