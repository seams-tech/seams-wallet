# リリース 0.45.0

ブラウザーSDK、サーバーSDK、VoiceIDは **0.45.0** です。

- **互換性のない変更:** VoiceIDのホストAPIはバージョン7から8になりました。`@seams/voiceid` 0.45.0と`@seams/wallet` 0.45.0を一緒にインストールし、ウォレットホストを再度作成してください。
- VoiceIDのセッションがない、期限切れ、または使い切られた場合、次の署名操作はウォレット内でVoiceIDをもう一度求め、その後に署名します。パスキーを求めることはありません。確認済みのリクエストでは、確認画面を開く前に音声確認を行います。
- 再認証が必要になった時点で所有者がすでにリクエストを承認していた場合、音声確認の後の再試行は、2回目の **Confirm** なしで署名します。
- 選択中の方式がVoiceIDのウォレットは、そのエクスポートに結び付いた音声確認をもう一度行うと、NEAR Ed25519とEVM ECDSAの鍵をエクスポートできます。パスキーやEmail OTPを求めることはありません。先に`@seams/wallet-server` 0.45.0をデプロイしてください。Routerは、このバージョンから新しい`voiceid_device`のエクスポート認可を受け付けます。
- 確認カードは、必要な時間だけ待つようになりました。確認画面の有効期限切れとキャンセルは、これまでどおりリクエストを終了します。そのほかの手順は、60秒の制限のままです。
- 正確なセッション状態で、VoiceIDのセッションが無効と判定されることはなくなりました。
- ホスト型の認証メニューに、閉じる **×** ボタンは表示されなくなりました。Escapeキーで閉じるか、方式を選んでください。

Walletのiframeプロトコルは **23.0.0**、ウォレット管理プロトコルは **5** のままです。
署名付きの復元CLIは **0.29.0** のままです。このリリースにデータベースのマイグレーションはありません。

## リリース 0.44.0

ブラウザーSDK、サーバーSDK、VoiceIDは **0.44.0** です。

- **互換性のない変更:** VoiceIDはパスキーと同じように動作します。VoiceIDでアンロックすると、通常の署名セッションが開きます。このセッションは、パスキーのセッションが署名できるすべての操作を、すべてのチェーンとネットワークで署名します。取引ごとの音声照合はなく、通常の **Confirm** を表示します。詳しくは[VoiceID](/ja/concepts/auth-methods/voiceid#unlock-and-approve-transfers)を参照してください。
- このため、音声の一致でメインネットの価値ある取引を承認できます。VoiceIDは実験的な機能です。話者類似度のしきい値は **0.45** で、録音や合成音声への耐性は本番環境での保証ではありません。
- **互換性のない変更:** 公開の署名オプション`options.voiceId`と、取引ごとのVoiceID承認を削除しました。署名呼び出しから`options.voiceId`を削除してください。
- **互換性のない変更:** VoiceIDのホストAPIはバージョン6から7になりました。`@seams/voiceid` 0.44.0と`@seams/wallet` 0.44.0を一緒にインストールし、ウォレットホストを再度作成してください。
- VoiceIDのセッションで新しい認証が必要になると、所有者はVoiceIDで再度アンロックします。鍵のエクスポートには、引き続きパスキーまたはEmail OTPが必要です。
- VoiceIDの直接アンロックで **Unlock with VoiceID** が再び表示されます。0.43.0ではボタンが表示されず、VoiceIDの直接アンロックを開始できませんでした。
- React StrictModeの開発ビルドで、設定ダイアログが再び開くようになりました。

Walletのiframeプロトコルは **23.0.0**、ウォレット管理プロトコルは **5** のままです。
署名付きの復元CLIは **0.29.0** のままです。このリリースにデータベースのマイグレーションはありません。

- 最初の設定スナップショットが、すでに読み取ったウォレットを示す場合、ページ読み込み時のセッション読み取りが1回減ります。

## リリース 0.41.1

ブラウザーSDK、サーバーSDK、VoiceIDは **0.41.1** です。

- `ft_transfer` または `ft_transfer_call` のアクションが1つだけで、添付額がちょうど 1 yoctoNEAR のNEARリクエストでは、トークン金額を見出しに表示します。確認画面には最終的な受取人とトークンコントラクトを表示し、詳細ではこの添付額を必須のセキュリティデポジットとして示します。
- シンボルと小数桁数は、ウォレット自身のリストまたはトークンコントラクトの `ft_metadata` から読み取ります。アプリケーションの値は使いません。メタデータを2秒以内に取得できない場合は、正確な基本単位の値を表示します。
- 公式の図柄を使うのは、ウォレットのリストにあるトークンだけです。リストにないコントラクトがリスト上のシンボルを名乗ると、警告を表示します。
- ほかのアクションやNEARの添付がある場合は、NEARの金額を見出しのままにし、トークン転送は行として併せて表示します。
- ネイティブ値のないERC-20の `transfer` 呼び出しでは、トークン金額を見出しに表示し、最終的な受取人とトークンコントラクトも表示します。トークン名を示すのは、そのチェーンのウォレットのリストにあるトークンだけです。ほかのトークンは正確な基本単位の値を表示します。コントラクト自身のシンボルは証明にならないためです。
- EthereumとBaseのネイティブ値は、weiではなくETHで表示します。
- 確認画面にBTC、ETH、stNEAR、NEAR、USDC、USDT、SOL、ZECの図柄と、WBTCなどリストにあるラップ版の図柄を追加しました。
- 長い金額は折り返すため、すべての桁が見えます。
- トランザクションの詳細では、0.00001 NEAR未満の添付額を `0 NEAR` とせず正確に表示します。スクロールバーはウォレットのテーマに従います。

Wallet iframeプロトコルは **23.0.0**、ウォレット管理プロトコルは **5** のままです。

- SDK 0.40.0以前の記録は、書き込んだURLで開いたときにネットワークへの紐づけに移行します。RPC URLを変更する前に開くか完了してください。

## リリース 0.40.0

ブラウザーSDK、サーバーSDK、VoiceIDは **0.40.0** です。

- 所有者NEARのレシートは、最初の送信前に署名鍵、nonce、参照ブロック、送信段階を保存します。
- 確定ブロックが期限切れの取引が未実行であることを証明した場合、復元は `proof.execution: 'not_executed'` を持つ `retired` を返します。
- NEARが今後の実行を拒否しても過去の未実行を証明できない場合、復元は `retirement_available` を返します。`retire()` にはWalletオリジンでの新しい所有者パスキー承認が必要です。
- SDK 0.39.0以前のハッシュだけのレシートは、SDK 0.40.0で最初に復元した後、有効期間が過ぎるまで未解決のままです。
- 退役処理は再送信せず、対応する保留操作だけを解除します。

Wallet iframeプロトコルは **23.0.0** になります。ウォレット管理プロトコルは **5** のままです。
古いブラウザーSDKは0.40.0のホスト型Walletに接続できません。ブラウザーSDK、ホストアセット、サーバーSDK、VoiceIDを同時に更新してください。
署名付き復元CLIは **0.29.0** のままです。このリリースにはデータベースの移行はありません。

## リリース 0.39.0

ブラウザーSDK、サーバーSDK、VoiceIDは **0.39.0** です。

- ウォレットの読み込み中もページのクリック、入力、フォーカスを維持します。内容の準備ができてからモーダルを開きます。
- NEAR所有者操作の復元では、モーダルと承認待ち行列を使いません。承認操作ではモーダルを使います。
- 復元の通信期限は35秒です。進捗通知では延長せず、遅れた応答も別の承認を妨げません。
- 状態照会には `tx` と `wait_until: 'NONE'` を使います。不明または未確定の結果は保留状態を維持し、再送信しません。
- 状態照会の前に保存済みのハッシュを公開します。以前の操作で保留になったハンドルは、復元の進捗とエラーでも元の操作IDを保持します。

Wallet iframeプロトコルは **22.0.0**、ウォレット管理プロトコルは **5** のままです。
署名付き復元CLIは **0.29.0** のままです。SDK、ホストアセット、サーバー、VoiceIDを同時に更新してください。
このリリースにはデータベースの移行はありません。トランザクションが見つからないことだけでは未送信を証明できず、過去の記録を安全に破棄できません。

## リリース 0.37.0

## リリース 0.36.0

ブラウザーSDK、サーバーSDK、VoiceIDは **0.36.0** です。

- NEAR所有者操作の `failed` を `not_submitted` と `recovery_unavailable` に分離します。
- `unresolved` はトランザクションハッシュと復元IDを保持します。SDKが返すIDを保存してください。
- 送信前にハッシュを公開します。ブラウザーの記録がないことだけでは未送信を証明できません。
- 送信と状態照会は30秒で待機を終了します。タイムアウト後も不確実な結果を保持し、再送信しません。
- 確定したリバートを直ちに返します。記録の書き込み失敗は、確認済みの結果を変更しません。
- サンプルは再読み込み後もハッシュを保持し、未解決の操作の置き換えを防ぎます。
- アプリ認証と所有者証明の再試行は、元の認可と接続を保持します。
- VoiceIDの登録、有効化、承認はWalletホストの明示的な状態を使います。

Wallet iframeプロトコルは **22.0.0** になります。アプリのSDKとWalletホストアセットを同時に更新してください。
古いiframeプロトコルでは接続できません。アプリのSDK更新が必要です。
サーバーSDKとVoiceIDも同じパッケージバージョンに更新してください。
署名付き復元CLIは **0.29.0**、ウォレット管理プロトコルは **5** のままです。

### 復元の安全性 {#recovery-security}
