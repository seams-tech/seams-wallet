# リリース 0.27.0

バージョン **0.27.0** は、カスタマイズ可能なウォレット接続メニュー、テーマ対応、NEARの結果表示、VoiceIDの読み込み復旧を追加します。

| コンポーネント | バージョン |
| --- | --- |
| ブラウザーSDK `@seams/wallet` | **0.27.0** |
| サーバーSDK `@seams/wallet-server` | **0.27.0** |
| オプションプラグイン `@seams/voiceid` | **0.27.0** |
| ネイティブCLIランチャー `@seams/wallet-cli` | **0.25.0** |
| Wallet iframeプロトコル | **17.0.0** |

- `WalletConnectorMenu`は、公式アイコン、文言の変更、認証画面への連続した切り替えを提供します。
- 戻る操作でウォレット選択へ戻れます。接続メニューと認証成功表示はSDKのテーマを使います。
- 取引詳細は画面内でスクロールでき、レシートの切り替えで文字がずれません。
- NEARの送信前失敗、送信状態不明、実行結果未確定を区別します。
- VoiceIDの読み込み失敗から再試行でき、マイク入力を試行間で統一します。

ブラウザーSDK、Walletホストアセット、サーバーSDK、有効なVoiceIDプラグインを同時に更新してください。

## リリース 0.26.0

バージョン **0.26.0** は、パスキーのコールド復元後にブラウザーの権限情報が古いまま残る問題を修正します。

| コンポーネント | バージョン |
| --- | --- |
| ブラウザーSDK `@seams/wallet` | **0.26.0** |
| サーバーSDK `@seams/wallet-server` | **0.26.0** |
| オプションプラグイン `@seams/voiceid` | **0.26.0** |
| ネイティブCLIランチャー `@seams/wallet-cli` | **0.25.0** |
| Wallet iframeプロトコル | **17.0.0** |

- 復元で検証したEd25519のアクティベーションを保存し、置き換えられたローカルのシールを削除します。既存の古い権限情報も、通常のパスキーアンロックで修復できます。
- 権限の識別情報、許可、失効、同時ロックの確認は維持します。遅れて届いた応答は、新しいセッションを置き換えません。
- ブラウザーのTLSによるパスキー拒否では、信頼されたHTTPSを使うよう案内します。ユーザーによるキャンセルはエラーとして表示しません。
- デバイス連携にはWalletオリジン内での明示的な承認が必要です。親アプリから承認を渡すことはできません。

アプリのSDKとホストするWalletアセットを同時に更新してください。VoiceIDには同じバージョンのプラグインを使ってください。
ブラウザーSDK **0.25.0** は、復元後に古い権限情報が残り、次のアンロックに失敗することがあるため、使用を避けてください。

## リリース 0.24.0 {#release-0-24-0}

バージョン **0.24.0** では、VoiceIDの登録、アンロック、NEARおよびArcテストネットの取引承認を利用できます。

| 構成要素 | バージョン |
| --- | --- |
| ブラウザーSDK `@seams/wallet` | **0.24.0** |
| サーバーSDK `@seams/wallet-server` | **0.24.0** |
| オプションプラグイン `@seams/voiceid` | **0.24.0** |
| Wallet iframeプロトコル | **17.0.0** |

VoiceIDのモデルと推論コードは、別パッケージの `@seams/voiceid` に含まれます。
基本のWalletパッケージには、VoiceIDのモデルや推論エンジンは含まれません。
`voiceIdAuthMethod` を `@seams/voiceid` からインポートし、`authMethods` で明示的に有効にします。
Walletホストの運用者は、`seams-voiceid-host ./wallet-with-voiceid`でプラグインのアセットを配置します。
アプリとホストの手順は[VoiceIDの設定](/ja/concepts/auth-methods/voiceid)を参照してください。
設定を有効にするだけでは、VoiceIDのダウンロードは始まりません。

初回のVoiceID操作では、エンジンと3つのモデルに共通の進捗バーを表示し、その後に **Preparing VoiceID…** を表示します。
音声サンプルは、所有者が変更または削除するまで保持されます。話者照合のしきい値は0.5です。
`VoiceBeam` と `VoiceAssistantCard` は `@seams/voiceid/react` から、カードのスタイルは `@seams/voiceid/styles` から読み込みます。

## リリース 0.22.0 {#release-0-22-0}

このドキュメントは、ブラウザーSDKとサーバーSDKのバージョン**0.22.0**を対象とします。復元CLIは**0.21.0**です。

2026-10-25に準備しました。npmへの公開と各ホスト環境へのデプロイは、個別に確認してください。

### 0.22.0の変更点 {#changes-in-0-22-0}

- アンロックメニューは、認証の準備中に保存済みウォレットを表示します。
- トランザクション設定には、確認スイッチとモーダルまたはドロワーの表示形式があります。
- NEP-413メッセージ署名は、3本のトラックが埋まった完了レシートを表示します。
- デバイス連携の認証方法セレクターと「続行」ボタンは、ウォレットのテーマに従います。
- NEARリレイヤーは、アクセスキーと最新ブロックを並行して取得します。

| 構成要素                                    | バージョン | 要件                                                       |
| ------------------------------------------- | ---------- | ---------------------------------------------------------- |
| ブラウザーSDK `@seams/wallet`               | **0.22.0** | アプリのコードとウォレットオリジンのアセットを一致させる   |
| サーバーSDK `@seams/wallet-server`          | **0.22.0** | 連携するバックエンドの各ロールをデプロイする               |
| ネイティブCLIランチャー `@seams/wallet-cli` | **0.21.0** | 署名済みネイティブアセットとダッシュボードのコマンドを使う |
| ウォレットiframeプロトコル                  | **16.0.0** | アプリとウォレットホストを一致させる                       |

CLIは公開前に交換した新しい復元ルートを固定します。以前のルートで署名した復元パッケージには、
新しいパッケージと証明書が必要です。古いルートとの継続ブリッジはありません。

### 復元の安全性 {#recovery-security}

ブラウザーSDKは、復元の認証情報をサーバーへ送る前にパスキーPRF出力を取り除きます。
サーバーは、拡張機能の出力値が残る復元の認証情報と登録情報を拒否します。
ECDSA署名の追加認証と鍵エクスポートの証明もPRF出力を送らず、サーバーは除去済みの認証情報だけを受け付けます。
復元の管理には、操作に結び付いた新しい完全所有者の証明が必要です。

### ドキュメント {#documentation}

日本語ドキュメントは、デプロイ、復元、実装例、APIリファレンスを含むサイト全体に対応しました。
形式検証のドキュメントでは、証明済みの不変条件、仮定、残る作業を区別します。

### ホストするウォレットの操作 {#hosted-wallet-controls}

- ホスト環境での認証は、成功を確認してから画面を閉じ、アプリへ結果を返します。
- メニューが開く前にキャンセルすると、ウォレットホストはメニューを表示しません。
- アカウントパネル、鍵のエクスポート行、QRカメラ画面は、狭い画面や拡大縮小したホストに収まります。

### 英語と日本語の表示 {#english-and-japanese-controls}

このリリースでは、ブラウザーSDKとサーバーSDKを`0.22.0`に統一します。復元CLIは`0.21.0`です。
ウォレットiframeプロトコルは16.0.0のままです。

プロバイダーの設定を作成する際に、SDKの言語を指定してください。

```tsx [部分的な実装例]
import { normalizeWalletLocale } from '@seams/wallet';

const appearance = {
  locale: normalizeWalletLocale(new URL(location.href).searchParams.get('locale')),
};
```

`appearance`を`defineSeamsConfig`または`SeamsWebProvider`の`config`へ渡します。
日本語には`appearance: { locale: 'ja' }`を使います。英語にはlocaleの指定を省略します。
プロバイダーとウォレットオリジンのUIは、この設定を共有します。
SDKのプレビューでも、`AccountMenuButtonMock`と`SeamsAuthMenuMock`の`locale`を指定できます。
アプリ独自の見出しやカスタム文言の翻訳は、アプリ側で用意してください。

Consoleのブラウザー・サーバーパッケージを正確な`0.22.0`に固定し、対応するウォレットオリジンのアセットをデプロイしてください。
アプリだけを更新しても、古いホスト環境のウォレットは翻訳されません。

### 導入 {#integration}

[はじめに](/ja/)に従ってブラウザーSDKをインストールしてください。
ウォレットホストとバックエンドについては、[ホスト環境への導入](/ja/deploy-and-operate/hosted-integration)を参照してください。
アプリのコードとウォレットのアセットを一緒にデプロイしてください。

Reactの`useSeams()`は、認証操作と現在紐づいている`wallet`を提供します。

```tsx [部分的な実装例]
const { unlock, lock, wallet } = useSeams();
```

サインアウト中のウォレットは`null`です。NEARアカウントの準備が整うまで、NEAR署名機能も`null`です。
署名前に`wallet?.near`を確認してください。アンロック完了後の認証済みレンダーからウォレットを取得してください。

登録時の既定動作では、サーバーがウォレットIDを割り当てます。
この動作には、`registerWallet`の`wallet`を省略してください。ウォレットを明示的に選ぶこともできます。
設定済みチェーンと既定のプロビジョニングを使うには、`signerSelection`を省略してください。
独自の署名対象も指定できます。

### デプロイ {#deployment}

対応するウォレットホスト、Gateway、Wallet Runtime、Router、コントロールプレーン、両Deriver、Signing Workerをデプロイしてください。
各Workerがトラフィックを処理する前に、同梱のD1マイグレーションを適用してください。

デプロイした各サービスのリリース識別情報を確認してください。パッケージの公開とホスト環境へのデプロイは別の手順です。
[本番環境の確認事項](/ja/deploy-and-operate/production-checklist)に従い、復元ツールに依存する前に[復元CLI](/ja/deploy-and-operate/recovery-cli)を確認してください。

### 準備中のNEARコネクター {#prepared-near-connector}

各ウォレットは`wallets`で明示的に有効化します。デモと実装例はMeteorのみを選択します。
`setWallets`による実行中の変更と、空のリストによる全無効化にも対応します。
設定は[外部NEARウォレットの選択](/ja/reference/configuration#external-near-wallet-selection)を参照してください。

**2026-10-26**に確認したnpmの最新ブラウザーSDKは`0.22.0`です。
外部NEARコネクターは`dev`に実装済みですが、**このリリースには含まれていません**。
新しいパッケージの公開やデプロイが完了したことを示すものではありません。

[コネクターガイド](/ja/guides/external-near-wallets)には、Meteor、HOT、Intear、
2つの新しいインポート先、開発版に対してコンパイルした実装例があります。
実際のMeteor拡張機能で、テストネット接続、ゼロデポジット取引の最終実行、コントラクトの正確な読み戻しを検証しました。
実際のHOT拡張機能でも、メインネット接続とポップアップを閉じた後の再試行を検証しました。
HOTの取引署名と、Intearの実ウォレット検証は未実施です。
公開と非公開アプリへの導入には、正確なSDKリリースバージョンが必要です。
